# 维修咖啡馆分诊单

打开 `index.html`。不收集姓名，也不把表发到服务器。

键盘实测：从页首连续 Tab，焦点依次是物品、已选的类别、危险选项、备注、分诊、清空重填。在危险的「否」上按空格会选中。在「分诊」上按回车会提交。成功后焦点落在「返回修改」，再按回车回到表单，物品文字还在。Tab 可以到达「下载 receipt.json」。点「布艺」这两个字会选中并聚焦对应单选。空提交后，焦点在表顶错误汇总，链接指向对应字段；物品带 `aria-invalid`，`aria-describedby` 含 `item-error`。危险分组的 `aria-describedby` 指向 `hazard-error`。41 个字符的物品和 101 个字符的备注被拒绝，原值还在。清空重填后，物品和备注为空，危险取消选择，类别回到纸品。

四个样例的分流：折角书签到纸艺桌（`paper-desk`），布袋到缝补桌，发热装置模型虽选纸品但仍不接收（`hazard-first`），木片到咨询桌。`receipt.json` 是折角书签、纸品、无危险这一次的导出。

已知限制：这次没有使用读屏软件，也没有对照完整的无障碍规范逐条打分。焦点环、标签、错误关联和上面的键盘路径是实测结果，不能据此说所有无障碍都已完美。
